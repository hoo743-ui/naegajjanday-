# 55. 관광지 · 문화시설의 실제 영업시간 (TourAPI detailIntro2) — 2026-09-26

> docs/51 의 **A1 영업시간(0.1%)** — 밤 · 월요일 코스가 업종 상식선(data/hours/default_hours.json)으로 짜여
> 문 닫은 궁궐 · 박물관 · 전망대로 사람을 보냈다. 한국관광공사 TourAPI `detailIntro2` 의 이용시간 · 쉬는날을
> 읽어 장소마다 실제 시간을 넣는다. 한 곳에 한 번 호출, 하루 1,000건 한도라 **매일 조금씩 이어받는다.**

## 무엇을 읽나

| contentTypeId | 종류 | 이용시간 | 쉬는날 |
|---|---|---|---|
| 12 | 관광지 | `usetime` | `restdate` |
| 14 | 문화시설 | `usetimeculture` | `restdateculture` |

값은 자유 문장이다: "09:00~18:00 (입장마감 17:00)", "[3월~5월] 09:00~19:00 …", "매주 월요일 (단, 공휴일인 경우 다음날)",
"점포별로 상이함", "상시 개방", "일출~일몰". 파서: `apps/api/app/infra/ingestion/hours_text.py`, 테스트 79개(실제 응답 문장).

## 파서 규칙 — 애매하면 넣지 않는다

틀린 "열림"은 밤에 닫힌 곳으로 사람을 보내고, 빈 값은 업종 상식선을 그대로 쓸 뿐이다. 그래서:

- **계절이 여럿** → 가장 좁은 하루(가장 늦은 개장 · 가장 이른 마감). 1년 내내 맞는다. 한 계절만 적혀 있으면(해수욕장 6~9월) 넣지 않는다.
- **입장 마감** → 마감 = 입장 마감 + 30분. 엔진은 "도착 뒤 30분 이상 열려 있나"를 보므로 입장 마감 시각이 마지막 도착이 된다.
  "관람 종료 1시간 전 입장 마감"처럼 상대 시간도 읽는다.
- **요일별** ("평일 · 주말", "[화~목, 일] … [금~토] …", "화~일 11:00~19:00 / 수요일 ~21:00") → 요일마다. 좁은 요일 이름이 넓은 것을 덮는다.
- **휴게 · 점심 시간** → break_start / break_end.
- **상시 개방 · 24시간** → 매일 00:00~00:00(24시간). 단 "상시"에는 두 가지가 있다(2026-09-26, 대기열 9):
  - "상시 개방" · "자유 관람" · "24시간" = 문이 없는 곳(공원 · 광장 · 거리 · 다리 · 한옥마을) → 24시간.
  - "상시운영" · "상시 영업" · "연중 운영" = 가게가 "팝업이 아니라 늘 있는 매장"이라는 말(영카이브 성수점 1층) → 문 닫는 시각을 말하지 않으니
    넣지 않는다(ambiguous). 예외: 이름 · 업종이 열린 공간(공원 · 거리 · 광장 · 다리 · 마을 …, `attraction.park|street`)이면 24시간.
  - 건물 안 업종(박물관 · 미술관 · 전시 · 서점 · 음식 · 카페 · 술집 · 체험 · 숙소 · 시장)은 "상시 개방"이라도 "24시간"이라고 적혀 있지 않으면 넣지 않는다
    (김만덕기념관 — 실제로는 09:00~18:00). 로컬 답 780건 중 바뀐 것: 영카이브 · 김만덕기념관 둘(24시간 → 업종 기본값), 나머지 237곳 그대로.
  - 해석기(`hours_text.py`)가 바뀌면 배포 때 data sync 가 저장된 답을 **호출 0건으로 다시 읽는다**(`rules/hours_text`, docs/57).
- **쉬는날**은 매주 되풀이되는 요일만. 명절 · 1월 1일 · 기념일(비정기)과 "매월 첫째 월요일"(매주 아님)은 요일 규칙이 아니라 뺀다.
  "(단, 공휴일인 경우 다음날)" 같은 예외 문장은 버린다. 쉬는날이 비어 있으면 업종 기본 휴무(문화시설 = 월요일)를 쓴다.
- **넣지 않는 것(ambiguous)**: 점포 · 공연 · 매장별 상이, 문의 · 예약제 · 변동, 일출~일몰, 시설이 여럿(정문/후문, 전시관/정원),
  상시 개방인데 시간도 적힌 것, 범위가 아닌 시각이 남는 것("18:00부터 내부 비개방", "마지막 해설 16:30"), 요일이 빠진 것.
  공연장(`culture.cinema`)의 이용시간이 21시 전에 끝나면 매표소 시간이라 넣지 않는다(공연은 밤에 한다).
- 원문은 언제나 `place_source.raw.intro` 에 남는다(fields · fetched_at · status · reason). 파서를 고치면 호출 없이 다시 읽는다.

## 적재기 `ingest-bulk tourapi-hours`

```
uv run python -m app.cli ingest-bulk tourapi-hours --limit 900      # 오늘 몫(한도 안에서)
uv run python -m app.cli ingest-bulk tourapi-hours --status         # 어디까지 왔나
uv run python -m app.cli ingest-bulk tourapi-hours --reapply        # 파서를 고친 뒤 저장된 답을 다시 읽기(0건)
uv run python -m app.cli ingest-bulk tourapi-hours --export data/bulk/delta/tourapi_hours.json
uv run python -m app.cli ingest-bulk tourapi-hours --from-file data/bulk/delta/tourapi_hours.json   # 0건
```

- **순서**: TourAPI 장소 중 코스 역할(CULTURE · ATTRACTION · NIGHTVIEW · ACTIVITY), 핫스팟 55곳(`data/regions/intros.json`) 반경 안이 먼저,
  그 안에서 CULTURE → ATTRACTION · NIGHTVIEW → ACTIVITY, 인기순.
- **이어받기**: 답을 받은 장소는 `raw.intro` 가 있으니 다음 실행이 건너뛴다. 따로 진행 파일이 없어 어느 서버에서 돌려도 이어진다.
- **한도**: `--limit` 과 한도 훅(docs/47, `api_usage`)이 말하는 오늘 남은 호출 − 예약분(`--reserve`, 기본 100: 사이트의 둘러보기 링크 몫) 중 작은 쪽.
  응답 헤더 `x-ratelimit-remaining` 이 예약분까지 내려가거나 TourAPI 가 한도 소진(429 · 코드 22)을 말하면 바로 멈춘다.
- **덮어쓰지 않는 것**: 다른 출처로 이미 시간이 있던 장소는 그대로 둔다(`kept_existing`). 우리가 넣은 시간은 다음 답 · 재해석으로 바뀐다.

## 운영(Render)에 올리기 — 권장: 오늘 것은 파일로, 내일부터는 Render 에서 직접

한도는 **키 하나에 하루 1,000건**이고 로컬과 Render 가 같은 키를 쓴다. 오늘 몫은 로컬에서 이미 썼으므로:

1. 오늘 받은 780건은 `apps/api/data/bulk/delta/tourapi_hours.json` 으로 저장소에 들어 있다 → Render 에서 **호출 0건**으로 불러온다.
2. 내일부터는 **Render 에서 직접** 하루 한 번 돌린다(키가 같고, 진행 상태가 DB 에 있으므로 파일을 주고받을 필요가 없다).
   로컬에서는 더 돌리지 않는다(같은 한도를 나눠 쓰게 된다). 로컬 DB 가 필요하면 Render 에서 `--export` 한 파일을 `--from-file` 로.

Render Shell (서비스 › Shell):

```
cd /opt/render/project/src/apps/api
.venv/bin/python -m app.cli ingest-bulk tourapi-hours --from-file data/bulk/delta/tourapi_hours.json
.venv/bin/python -m app.cli ingest-bulk tourapi-hours --status
# 내일부터 하루 한 번 (핫스팟 남은 144곳 → 나머지 1만 5천여 곳, 하루 800곳씩 약 20일)
.venv/bin/python -m app.cli ingest-bulk tourapi-hours --limit 800
```

**cron**: Render 의 Cron Job 은 별도 유료 서비스이고, 웹 서비스의 영구 디스크(/var/data 의 SQLite)를 붙일 수 없어 이 DB 에 쓸 수 없다.
그래서 render.yaml 에 추가하지 않았다(유료 자원 금지). 당분간 위 한 줄을 Shell 에서 하루 한 번 — 무료로 자동화하려면
(1) 관리자 화면에 "영업시간 이어받기" 버튼(API 안에서 같은 함수 호출) 또는 (2) GitHub Actions 스케줄이 그 관리자 엔드포인트를 부르는 방식을 다음에 만든다.
운영계정 트래픽 증설(활용사례 등록, docs/51 §4)이 되면 `--limit` 만 올리면 된다.
