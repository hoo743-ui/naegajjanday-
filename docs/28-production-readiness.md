## 1. 전체 상태 요약 (점검 시점)
핵심 여정(랜딩 → 위저드 → 결과 → 지도 · 이동 → 공유)은 끝까지 간다. 코스 생성 대기 약 4초, 여섯 폭(390 · 430 · 768 · 1024 · 1280 · 1440) × 8화면에서 가로 넘침 0.
그러나 **공유한 코스를 남이 고칠 수 있었고**, 평균가로 계산한 합계를 확정값처럼 보여 주었고, 가격을 모르는 곳을 "무료"로 찍을 수 있었다.
저장은 로그인이 필요한데 **이 환경에는 소셜 로그인 키가 없어** 저장까지 갈 수 없다(배포 설정 문제).

## 3. 분야별
- **UX**: 결과 화면 5초 규칙(어디 · 몇 명 · 예산 · 얼마 · 남은 돈 · 순서) — 헤더(지역 · 목적 · 인원 · 예산) · 짠이 한마디(남은 돈) · 영수증 · 지도/이동이 첫 화면. 위저드에서 뒤로 가도 고른 값이 남는다. 공유받은 사람에게 다음 행동이 보인다.
- **애니메이션**: 계속 움직이던 이벤트 띠는 앞 단계에서 멈췄다. 인트로는 탭당 한 번 · 아무 입력에 걷힘 · 모션 최소화면 없음. 바텀시트 단계를 바꿔도 읽던 카드는 제자리. 남은 것: 스크롤 등장(Reveal)이 전체 페이지 캡처에서 덜 끝나 보인다(실사용 문제 아님, P3).
- **성능**: 첫 이미지 priority. 경로 · 추천 · 공연 · 행사는 코스 화면을 막지 않고 뒤에서 받는다. 공연(KOPIS)은 요청당 최대 17초 — 스켈레톤이 오래 남는다(P2, 서버 캐시 권장).
- **모바일**: 390 · 430 에서 여정 A · D 통과, 가로 넘침 0, 하단 저장 버튼 56px.
- **API / 데이터**: 금액은 장소 합 = API = 영수증 = 남은 돈. 경로는 실측 · 추정 · 계산 못 함을 구분(docs/27). 가격 97.9% 는 추정 — 이제 화면이 그렇게 말한다.
- **접근성**: aria-hidden 경고 제거, 순번 = "지도에서 N번 보기" 버튼(키보드), 44px 이상 터치.
