## 원문

현재 1단계 Typography 작업은 이미 적용되었다.
이제 폰트는 다시 크게 변경하지 말고,
사이트 전체의 레이아웃, 정보 구조, 컴포넌트 배치, 여백, 시각적 리듬을 재설계하라.

목표는 단순히 "더 예쁜 웹사이트"가 아니다.
현재 사이트에서 느껴지는 "AI가 자동으로 만든 프리미엄 스타트업 웹사이트" 느낌을 제거하고,
"내가짠데이라는 하나의 독립적인 생활 서비스 브랜드" 처럼 보이게 만들어라.

### 1. 절대 유지해야 하는 핵심
서비스의 핵심은 절대 바꾸지 않는다.
내가짠데이 = "예산을 말하면 AI가 하루 코스를 짜서 영수증으로 보여주는 서비스"

브랜드의 핵심 시각 언어: 하루 · 예산 · 돈 · 영수증 · 이동 · 코스 · 짠이.
이 7개를 사이트 전체의 디자인 언어로 사용하라.
새로운 기능을 임의로 추가하지 말 것. 기존 기능, 데이터, API, 사용자 플로우를 삭제하지 말 것.
이번 작업은 철저하게 "브랜드 경험과 레이아웃 개선"에 집중한다.

### 2. 가장 먼저 해야 할 작업
전체 페이지를 하나씩 보면서 다음과 같은 전형적인 AI 웹사이트 패턴을 모두 찾아라.
- 대형 중앙 정렬 Hero
- 거대한 한 줄 슬로건
- 반복되는 둥근 카드
- 모든 정보를 카드 안에 넣는 구조
- 카드 → 카드 → 카드 식의 수직 나열
- 동일한 border-radius 반복
- 지나치게 동일한 여백
- 모든 요소가 가운데 정렬
- CTA 버튼이 모든 섹션에서 반복
- "AI가 ~해드립니다" 식의 과도하게 친절한 문장
- 너무 완벽하게 대칭적인 레이아웃
- SaaS dashboard 같은 섹션 구성
- 의미 없는 장식용 gradient
- 의미 없이 floating 하는 UI
- 모든 정보를 box 안에 가두는 방식

이러한 패턴이 발견되면 단순히 스타일을 바꾸지 말고 레이아웃 구조 자체를 재검토하라.

### 3. 내가짠데이만의 레이아웃 언어 구축
사이트 전체에서 아래 4개의 레이아웃 패턴을 반복적으로 사용하라.

**A. RECEIPT LAYOUT** — 영수증을 단순한 카드로 사용하지 말고 서비스의 핵심 인터페이스 언어로 사용한다.

```
오늘의 예산
₩50,000
────────────────
식사             ₩18,000
카페              ₩8,000
데이트            ₩20,000
────────────────
남은 금액          ₩4,000
```

이 구조를 Landing / Result / Share / My / Summary 등에 자연스럽게 반복한다.
단, 모든 것을 실제 영수증 모양으로 만들지는 말 것. 영수증의 구분선 · 항목 구조 · 숫자의 위계 · 상하 흐름 · tear-off feeling 만 가져온다.

**B. ROUTE LAYOUT** — 이동 경로를 단순한 지도 기능이 아니라 브랜드 그래픽 언어로 사용한다.
(집 ↓ 점심 ↓ 카페 ↓ 전시 ↓ 저녁) 지도에만 route를 두지 말고 페이지 내부의 콘텐츠 흐름에도 route의 개념을 적용하라.

**C. DAY FLOW** — 사용자가 하루를 "시간순으로 소비한다"는 점을 시각적으로 보여준다.
(12:00 점심 · 14:00 카페 · 16:30 산책 · 18:30 저녁) 각 장소를 무조건 카드로 만들지 말고 timeline / list / receipt item / image block 등을 섞어서 사용한다.

**D. MONEY AS VISUAL OBJECT** — 가격은 단순한 작은 텍스트가 아니다.
총 예산 · 사용 금액 · 남은 금액 · 장소별 예상 비용은 크기와 공간을 충분히 사용한다.
다만 가격을 모든 화면의 가장 큰 숫자로 만들지는 말고 "필요한 순간 강하게 보이게" 한다.

### 4. Landing Page 재구성
Hero를 다시 점검한다. 절대로 "대형 문구 + 오른쪽 카드" 형태의 전형적인 AI SaaS Hero를 만들지 않는다.
Hero는 "서비스 사용 장면"처럼 보여야 한다. 사용자가 페이지에 들어왔을 때 예산 → 오늘의 하루 → 영수증 이라는 흐름이 자연스럽게 보이도록 구성한다.
예시 방향: "오늘 쓸 수 있는 돈이 이만큼이라면," [₩50,000] 오늘은 점심 → 카페 → 산책 → 저녁 그리고 마지막에 [오늘의 영수증].
문구를 억지로 위 예시와 동일하게 만들 필요는 없다. 중요한 것은 "광고를 보는 느낌"보다 "서비스가 어떻게 작동하는지 직접 보는 느낌"이다.
Hero에서 큰 제목 하나 · CTA 하나 · 장식 몇 개 만 보여주는 방식에서 벗어나라. 서비스 자체가 Hero가 되게 한다.

### 5. Section 간 연결 방식 개선
현재 페이지가 Hero ↓ 카드 ↓ 카드 ↓ 카드 ↓ CTA 처럼 끊겨 보이지 않는지 확인한다.
각 섹션이 이전 섹션의 결과처럼 느껴져야 한다.
(예산 입력 ↓ 오늘의 조건 ↓ AI가 짠 하루 ↓ 영수증 ↓ 지도/이동 ↓ 실제로 하루를 보내는 모습)
섹션을 독립적인 마케팅 블록으로 만들지 말고 하나의 사용자 여정처럼 연결한다.

### 6. 카드 사용 제한
카드는 기본 레이아웃이 아니라 "정보를 묶어야 할 때만 사용하는 컴포넌트"로 바꾼다. 모든 섹션이 카드로 보이면 안 된다.
카드 대신: 큰 여백 · divider · timeline · receipt line · full-width image · text block · editorial layout · horizontal flow · map · 리스트.
장소 정보는 모든 장소를 동일한 카드로 반복하지 않는다.
핵심 장소 → 큰 이미지 + 핵심 정보 / 보조 장소 → compact row / 시간 정보 → timeline / 가격 → receipt item.

### 7. 비대칭 레이아웃 적극 활용
모든 것을 50:50으로 나누지 않는다(60/40 · 70/30 · 40/60).
실험적인 포트폴리오 사이트처럼 난해하게 만들지는 말 것. 목표는 "규칙은 있지만 템플릿처럼 보이지 않는 디자인".

### 8. 한국적인 느낌의 구현 방식
한옥/기와/한지 그래픽으로 직접 표현하지 않는다. 대신 한국어 문장의 줄바꿈 · 여백 · 종이 질감 · 영수증 · 골목과 도시의 선형 구조 · 간판/지도에서 느껴지는 도시성 · 소박한 정보 디자인 · 생활 서비스의 친숙함.
"한국적인 AI 서비스"가 아니라 "한국에서 실제로 만들어져 사람들이 쓰는 서비스" 처럼 보여야 한다.

### 9. 짠이 캐릭터 사용 방식
decorative sticker처럼 반복해서 붙이지 않는다. 등장 빈도를 줄이고 역할을 부여한다.
예산을 알려줄 때 · 코스가 완성될 때 · 예산이 부족할 때 · 장소를 바꿨을 때 · 사용자를 안내할 때 — "상황에 반응하는 companion". 무조건 화면에 떠 있는 캐릭터가 아니다.

### 10. 버튼 / CTA 재설계
CTA를 모든 섹션마다 크게 넣는 구조를 제거한다. 실제로 행동해야 하는 지점에서만 강조한다.
예산 입력 → "이 예산으로 짜기" / 코스 결과 → "이 장소 바꾸기" / 완성 → "영수증 저장하기".
"시작하기 / 자세히 보기 / AI 추천 받기" 같은 추상적인 CTA 남발을 줄인다.

### 11. Result Page는 가장 중요하게 재설계
마케팅 웹사이트 느낌을 완전히 제거한다. "그래서 오늘 어디 가면 되는데?"를 3초 안에 이해할 수 있어야 한다.
첫 화면에 바로: 오늘의 예산 · 남은 금액 · 오늘의 코스 · 예상 이동시간 · 전체 소요시간.
그 다음 하루의 흐름(12:00 점심 · 14:00 카페 · 16:30 이동 · 18:00 전시 · 19:30 저녁).
지도와 리스트가 경쟁하지 않게: 지도는 "어디로 이동하는지", 리스트는 "무엇을 하는지".

### 12. 모바일은 별도로 생각
Desktop을 줄여서 Mobile로 만들지 않는다. 예산 ↓ 오늘의 코스 ↓ 시간 ↓ 장소 ↓ 이동 ↓ 영수증 순.
Result 화면은 Bottom Sheet / Sticky Summary / Timeline 등으로 지도와 일정이 서로 가려지지 않도록 한다.

### 13. 시각적 리듬
모든 섹션의 padding을 동일하게 적용하지 않는다. 큰 섹션 → 큰 여백 / 정보 밀도가 높은 영역 → 작은 여백 / Hero → 넓게 / 영수증 → 촘촘하게 / 장소 리스트 → 읽기 좋게.
"8px grid를 지키는 것"보다 "콘텐츠의 의미에 따라 밀도가 달라지는 것"을 우선한다.

### 14. 이미지 사용
이미지는 카드 안에 넣는 장식물이 아니다. 핵심 장소는 이미지를 크게, 보조 장소는 이미지가 없어도 성립하도록.
모든 장소에 동일한 비율의 이미지가 들어가서 Pinterest처럼 반복되지 않게 한다.
이미지가 없는 경우 억지 placeholder 이미지를 채우지 않는다. 데이터 신뢰도가 낮다면 텍스트 정보가 중심이 되도록 한다.

### 15. 최종 디자인 테스트
실제로 실행해서 최소 Landing · Plan Wizard · Course Result · Place Detail · Save/Share · My · Mobile Landing · Mobile Result 를 직접 확인한다. 각 화면에서:
- 이 화면이 일반적인 AI SaaS처럼 보이는가?
- 카드가 너무 많은가?
- 중앙정렬이 과한가?
- 서비스의 핵심인 돈 / 하루 / 영수증 / 이동이 보이는가?
- 사용자가 무엇을 해야 하는지 바로 이해되는가?
- 짠이가 이유 없이 등장하지 않는가?
- **이 화면만 캡처해도 "내가짠데이"라고 알아볼 수 있는가?** (가장 중요)

"예쁜가?"보다 "다른 서비스로 대체할 수 없는가?"를 기준으로 수정한다.

### 16. 금지사항
Apple clone · Notion clone · Linear clone · generic AI SaaS · glassmorphism · neon gradient · 지나친 3D · 과도한 blur · 둥근 카드 남발 · dashboard 느낌 · 전형적인 AI sparkle icon · "AI" 텍스트 장식 남발 · 전통문화 이미지를 이용한 억지 한국풍 · 의미 없는 애니메이션 추가.

| 모바일 결과 | 지도 40% 아래 시트의 첫 화면이 말풍선 · 안내 · 탭 · 영수증 머리. 장소는 세 번째 화면부터 | 모바일 순서 |
| 위저드 | 질문마다 흰 둥근 카드, 지역은 둥근 카드 격자(아이콘 + 이름 + 숫자 + ›) | 모든 것을 상자에 |
| 내 코스(빈 상태) | 가운데 큰 짠이 + 가운데 제목 + 버튼 둘 | 중앙 정렬 |

**가장 심각한 셋**: ① 히어로의 "슬로건 + 카드" 구도 ② 결과 화면이 답(하루의 순서)보다 장식(말풍선 · 영수증 카드)을 먼저 보여 주는 순서 ③ 모든 것이 같은 반지름의 흰 상자라는 것.

### 2. 레이아웃 언어 — 네 가지 부품으로만 짠다

1. **영수증 줄(ledger)** — `이름 ········ 금액`. 구분선은 점선(`receipt-rule`), 끝은 톱니 · 구멍 줄(`tear-line`). 실제 영수증 모양(`<Receipt>`)은 **한 화면에 한 번**(랜딩 03 · 결과 화면의 "오늘의 영수증" · 위저드 옆)만.
2. **경로(route)** — 점(들르는 곳) + 선(이동). 가로로는 히어로 · 결과 화면 요약의 "하루 한 줄", 세로로는 결과 화면의 일정 · 랜딩의 단계.
3. **하루(day flow)** — 왼쪽에 시각(같은 폭 숫자), 가운데 선, 오른쪽에 할 일. 결과 화면의 일정이 이 모양이다.
4. **돈(money)** — 남은 돈 · 오늘 쓸 돈만 크게(`text-price-lg`). 장소 가격은 영수증 줄의 오른쪽 끝.

상자(흰 카드)는 정보를 묶어야 할 때만: 결과 화면에서는 "핵심 장소" 사진 한 장, 시트 · 대화상자. 반지름은 두 가지만: 사진 · 입력 8px, 칩 둥글게. 카드용 24px 반지름은 쓰지 않는다.
