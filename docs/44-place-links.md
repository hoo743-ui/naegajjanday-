# 44. 더 알아보기 링크 — 검색 목록이 아니라 그 장소의 페이지로

> 2026-09-24 창업자: "둘러보기에서 후기나 여러 가지를 누르면 그냥 카카오맵 검색으로 뜨는 경우가 다반사 — 후기나 홈페이지로 바로."

## 무엇이 어디로 가나
| 순서 | 링크 | 어디서 찾나 | 못 찾으면 |
|---|---|---|---|
| 1 | 공식 홈페이지 | 축제: 전국문화축제표준데이터 `event.booking_url`(1,068건 중 700건) · 장소 · 관광공사 행사: TourAPI `detailCommon2.homepage`(이미 가진 contentid) | 뺀다. 관광 포털 첫 화면(korean.visitkorea.or.kr/)은 홈페이지로 치지 않는다 |
| 2 | 카카오맵 후기 · 사진 | 카카오 로컬 API 키워드 검색(이름 + 좌표 400m) → **이름이 비슷하고(≥0.6) 250m 안**, 또는 거의 같은 자리(60m, ≥0.4)일 때만 `place.map.kakao.com/{id}` | 카카오맵 검색(화면에 "카카오맵 검색 결과"로 밝힘) |
| 3 | 블로그 후기 | 네이버 블로그 검색 링크 "<구> <이름> 후기"(축제는 "<이름> 후기") | — |
| 4 | 길찾기 | 찾은 카카오 장소 id 로 `map.kakao.com/link/to/{id}`, 없으면 이름 + 좌표 | — |

- 축제 · 행사는 카카오 장소와 맞추지 않는다 — 같은 이름의 가게가 잡힌다.
- 긁어 오는 것은 없다: 공식 API 두 개(카카오 로컬 · 관광공사)와 남의 사이트로 가는 링크뿐.
- API: `GET /v1/places/{id}/links` · `GET /v1/events/{id}/links` (`app/services/link_service.py`). 두 API 를 동시에 부르고(첫 호출 약 1~2초), 결과를 일주일 캐시한다(실패가 섞이면 1시간).
- 웹: `AttractionSheet` 는 기본 링크를 바로 그리고, 서버 링크가 오면 바꾼다(`usePlaceLinks`). 링크마다 아래 줄에 출처 — 그 장소의 페이지면 "카카오맵" · 도메인, 검색이면 "… 검색 결과".

## 2026-09-24 실측 (공원 · 전시 · 문화공간 · 관광지 16곳)
카카오 장소 페이지로 바로 간 곳 15/16, 공식 홈페이지 13/16. 못 맞춘 곳(서천특화시장)은 검색으로 떨어진다.

## 남은 것
- 캐시는 지금 프로세스 메모리다(REDIS_URL 없음) → API 를 재시작하면 처음부터. 운영에서는 Redis.
- 코스 결과의 장소 시트(`PlaceSheet`)도 같은 링크를 쓸 수 있다(아직 연결 안 함).
- 네이버 검색 API 키가 생기면 블로그 링크를 "검색 결과"가 아니라 상위 글 두세 개로 바꿀 수 있다(제목 · 링크만, 본문 저장 없이).
