# 64. 요구사항 추적 — 창업자 원문 → 해석 → 합격 기준 → 측정 → 상태 (2026-09-27)

> 목적: 창업자가 말한 것과 우리가 만든 것 사이의 거리를 **한 표에서** 본다. 에이전트가 요구를 제 식으로 다시 해석하거나 잣대를 바꿔 통과하는 것을 막는다.

## 규칙

1. **원문은 고치지 않는다.** 창업자가 채팅에 쓴 문장을 그대로 옮긴다.
2. **해석은 창업자 승인 후에만 구현한다.** 표의 "승인" 칸이 비어 있으면 구현하지 않는다(버그 수정 · 문서 제외).
3. **합격 기준은 구현 전에 적고, 구현하는 커밋에서 바꾸지 않는다.** 바꾸려면 창업자 승인 + 따로 된 커밋(`docs/58` 지표 목표도 같다 — docs/65 의 잣대 고정 참고, 예정).
4. **측정은 코드로.** "에이전트가 확인했다"는 측정이 아니다. 테스트 · 점수표 · 운영 이벤트 중 무엇으로 재는지 적는다.
5. 상태: `승인 대기` · `구현 중` · `끝(커밋)` · `어긋남`(해석이 원문과 다르거나 잣대를 바꿔 통과한 것) · `누락`.
