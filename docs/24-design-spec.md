# 24. 디자인 명세 — 지금의 화면, 허술해 보이는 이유, 완성까지의 과제

> 이 문서는 **로컬에서만 도는 웹을 직접 볼 수 없는 개발자 · 디자이너**를 위한 것이다. 화면 캡처와 함께 읽으면 서비스를 띄우지 않고도 전체 디자인을 파악하고 작업을 나눠 가질 수 있다.
> 캡처: `docs/design/screens/`(대표 20장, 2026-09-22 기준). 전체 62장은 `apps/web` 에서 `node e2e/visual-audit.mjs ../../docs/design-handoff/screens` 로 다시 찍는다.
> 함께 볼 문서: 컨셉 `19-design-principles.md` · 리디자인 브리프 `21-premium-redesign-brief.md` · 검증 절차 `22-verification.md` · 다른 AI 에게 넘기는 프롬프트 `23-design-handoff-prompt.md`.

## 0. 한 장 요약
- **서비스**: 내가짠데이 — 예산을 말하면 AI 가 하루 코스를 짜서 **영수증**으로 보여 준다. 마스코트는 금색 동전 **짠이**. 한국어, 모바일 우선.
- **디자인 컨셉**: "조용한 영수증(Quiet Receipt)" — 따뜻한 종이 바탕, 깊은 잉크, 금색은 돈에만, 세리프 제목, 움직임은 돈 · 동선 · 짠이에만.
- **지금 상태의 정직한 평가**: 색 · 글꼴 · 시그니처(영수증)는 자리를 잡았다. 그러나 **화면 구성이 "같은 모양의 흰 카드를 세로로 쌓은 것"**이라 위계가 없고, 장소 카드의 버튼 줄이 복잡하며, 지도가 팔레트와 따로 놀고, 사진의 절반이 예시 사진이라 싸 보인다. → 4절의 진단과 6절의 과제 참고.
- **기술**: Next.js 15 · React 19 · Tailwind v4(토큰 = `apps/web/src/app/globals.css` 의 CSS 변수) · shadcn/ui(Radix) · `motion` · lucide. 부품은 `apps/web/src/components/**`.

## 1. 컨셉과 절대 규칙
한 문장: **예산만 말하면, 하루가 영수증으로 나온다.**

| 규칙 | 내용 |
|---|---|
| 주인공은 돈 | 화면에서 가장 공들인 글자는 금액. `tabular-nums` · extrabold · 좁은 자간. "약" · "~쯤" 금지, 추정이면 "평균가"라고 쓴다 |
| 시그니처는 영수증 | 톱니 절취선 · 점선 안내선 · 품목 → 예산 → 합계 → **남은 돈**. 랜딩 히어로 · 코스 결과 · 공유 이미지가 같은 모양 |
| 금색은 돈에만 | 남은 돈 · 가격 · 짠이. 안내 · 경고 · 장식에는 쓰지 않는다 |
| 그라데이션은 한 화면에 한 번 | 제목의 한 구절 정도. 유리 효과 · 네온 · 떠다니는 도형 · 과한 그림자 금지 |
| 움직이는 것은 셋 | 돈이 바뀔 때(금액이 굴러간다) · 동선(지도 핀) · 짠이. 나머지는 120~420ms 의 조용한 등장. 스크롤을 붙잡는 연출 금지 |
| 정직 | 평점 · 리뷰 · 혼잡도 자료가 없다 → 화면도 말하지 않는다. 예시 사진은 "예시 사진", 추정가는 "평균가" |
| 지금 보이는 것은 다 나온다 | 제목 · 버튼 · 링크 · 라벨 761개가 자동 검증(`npm run verify`)에 걸려 있다. 빼려면 이유와 대체를 적는다 |
| 접근성 | 대비 4.5:1 · 터치 44px · 키보드만으로 모든 흐름 · 포커스 링 · `prefers-reduced-motion` |

### 2.2 글자
- 본문 · UI: **Pretendard Variable**(굵기 450 본문 / 520 · 620 · 690 · 760). 제목: **Noto Serif KR 600/700** — `h1` 과 `font-serif` 를 붙인 큰 섹션 제목에만. 로고 · 영수증 상호 · 짠이 말풍선: **Jua**.
- 크기(지금 쓰이는 값): 히어로 `clamp(36px, 5vw, 62px)` · 섹션 제목 `clamp(29px, 4.2vw, 50px)` · 화면 제목 24~44px(화면마다 다르다: `text-2xl` · `28px` · `clamp(26px,4vw,36px)` · `clamp(28px,4vw,44px)`) · 카드 제목 15~17px · 본문 15~16px · 보조 12.5~13px · 금액 22~32px.
- 행간 본문 1.7, 제목 1.2~1.28. 자간 제목 −0.03em, 본문 −0.011em. `word-break: keep-all`.
- **문제**: 크기 계단이 화면마다 임의 값(`text-[13.5px]`, `text-[14.5px]`, `text-[15px]`, `text-[17px]` …)으로 흩어져 있다 → 6절 D-1.

### 2.3 모서리 · 그림자 · 간격
- 모서리: 카드 24px(`rounded-card`) · 입력/버튼 16px · 칩 알약 · 영수증은 직각 + 톱니. 일부 랜딩 카드는 32px · 28px 가 섞여 있다(정리 대상).
- 그림자 3단계: `shadow-soft`(놓여 있음) · `shadow-card`(떠 있음) · `shadow-float`(들어 올림 · 모달).
- 간격: 8pt 그리드. 페이지 좌우 `clamp(20px, 4vw, 32px)`, 본문 최대폭 1136px(좁은 단 720px), 섹션 상하 `clamp(72px, 9vw, 128px)`. 코스 패널 안 카드 사이는 일괄 16px — **리듬이 없다**(6절 A-1).

### 2.4 모션
| 무엇 | 값 |
|---|---|
| 길이 | 눌림 120ms · 호버 220ms · 등장 420ms · 화면 전환 520ms |
| 곡선 | `cubic-bezier(0.16, 1, 0.3, 1)`, 스프링 `cubic-bezier(0.34, 1.4, 0.64, 1)`은 눌림 · 짠이 · 핀에만 |
| 영수증 | 위에서 아래로 "출력" 0.7초 → 줄마다 30ms → 남은 돈 위로 빛이 한 번 |
| 금액 | 0.5초 동안 100원 단위로 굴러서 멈춤 |
| 지도 핀 | 순번대로 12px 위에서 내려앉음(90ms 간격, 한 번만) |
| 짠이 | 3px 숨쉬기(4초) · 표정 전환 · 팔 흔들기 |
| 주 CTA | 호버에서 빛이 한 번 지나감(0.9초) |

## 4. 왜 허술해 보이는가 — 진단
1. **위계가 없다.** 코스 패널의 모든 구획이 "흰 카드 · 24px 모서리 · 같은 그림자 · 16px 간격"이다. 영수증(주인공)과 요약 3칸(보조)과 안내 상자가 같은 무게로 보인다. 고급스러운 화면은 *하나를 크게, 나머지를 조용히* 한다.
2. **주인공이 스크롤 중간에 있다.** 영수증이 짠이 · 설명 · 동네 카드 · 탭 아래에 온다. 첫 화면에서 보이는 것은 조건 한 줄과 말풍선이다.
3. **조건 한 줄이 읽히지 않는다.** "1일차 / 2일 · 부산광역시 · 송도해수욕장 주변 → … · 여행 · 2명 · 예산 … · 9월 27일 · 11:00 출발"이 파란 13px 한 줄로 이어진다.
4. **장소 카드의 아래 절반이 도구 상자다.** 글자 링크 3개 + 아이콘 버튼 2개 + 알약 버튼 1개가 두 줄에 걸쳐 있고 모양이 제각각이다(모바일 캡처 참고).
5. **사진이 발목을 잡는다.** 절반이 업종 예시 사진이고 16:7 로 크게 깔린다. 같은 라떼 사진이 코스마다 나온다 → 싸 보이고, 진짜 사진과 구별도 안 된다.
6. **지도가 남의 옷을 입고 있다.** 카카오 기본 지도의 노랑 · 초록 · 주황 위에 파랑 → 보라 → 분홍 핀. 종이 톤 패널 옆에서 가장 시끄러운 면이다.
7. **베이지 한 가지로 모든 보조 면을 칠했다.** 금색 · 그라데이션을 걷어 낸 자리(칩 · 안내 상자 · 아이콘 타일 · soft 버튼)가 전부 `--paper-2` 다. 구별이 안 되고 밋밋하다.
8. **글자 크기가 계단이 아니라 비탈이다.** 12.5 · 13 · 13.5 · 14.5 · 15 · 15.5 · 17px 이 섞여 있다. 눈이 "같은 급"을 알아보지 못한다.
9. **글꼴이 셋이다.** Jua(로고 · 영수증 상호 · 말풍선) + 세리프(제목) + Pretendard. 둥근 Jua 와 세리프가 한 화면에서 부딪힌다.
10. **랜딩의 중간이 비슷비슷하다.** 3.1 참고.
11. **헤더가 결과 화면에서도 영업을 한다.** 코스를 보고 있는 사람에게 "무료로 추천받기"가 계속 떠 있다.
12. **빈 곳의 품질.** 로그인의 비활성 버튼 3개("준비 중이에요"), 대화 화면의 빈 상태, 404 가 서비스의 나머지보다 덜 다듬어져 있다.

## 5. 참고할 서비스 — 무엇을 배울 것인가
남의 화면을 베끼자는 것이 아니다. 각 서비스가 **한 가지를 아주 잘하는 지점**만 본다(이미지는 저작권이 있으므로 저장소에 넣지 않고, 공개 화면을 직접 본다).

| 서비스 | 볼 것 | 우리 화면에 옮기면 |
|---|---|---|

## 6. 완성까지의 과제 (우선순위 순, 각 항목은 독립적으로 작업 가능)

### A. 코스 결과 화면 — 가장 먼저
| # | 과제 | 끝난 상태 |
|---|---|---|
| A-1 | **패널의 위계 다시 짜기**: 첫 화면 = 조건 요약(칩) + **영수증**. 짠이 말풍선은 영수증 위에 작게 얹고, AI 설명 · "이런 동네예요" · 예산 도구는 영수증 아래 접힌 구획으로 | 데스크톱 첫 화면(900px)에서 영수증의 "남은 돈"이 보인다 |
| A-2 | **조건 한 줄 → 조건 칩 줄**: 날짜 · 시간 / 동네 / 목적 / 인원 / 예산을 아이콘 + 짧은 칩으로. 여행이면 "1일차 / 2일" 을 탭과 합친다 | 13px 파란 문장이 없어진다. 모바일에서 두 줄 이내 |
| A-3 | **장소 카드 재설계**: 금액을 이름과 같은 줄 오른쪽에 크게. 아래 도구는 주 1개("바꾸기") + 보조는 `⋯` 메뉴 또는 아이콘 줄(거리뷰 · 지도 · 순서). "왜 여기?"는 이유 상자를 누르면 펼쳐지게 | 카드 하단이 한 줄. 버튼 모양이 두 가지 이하 |
| A-4 | **사진 정책**: 그 가게의 실제 사진이면 크게(16:9), **예시 사진이면 작게**(72px 정사각 썸네일 또는 업종 아이콘 타일) | 예시 사진이 화면을 지배하지 않는다. 같은 사진의 반복이 눈에 띄지 않는다 |
| A-5 | **지도 톤 맞추기**: 핀을 잉크색 물방울 + 흰 숫자(선택된 것만 파랑), 경로선은 파랑 한 가지, 구간 칩은 흰 바탕. 카카오 지도는 스타일 변경이 제한적이므로 위에 아주 옅은 종이색 오버레이(불투명도 8~12%)를 시험 | 지도와 패널이 한 화면으로 보인다 |
| A-6 | **모바일 바텀시트**: 지도 40% 고정 대신 3단(접힘 120px · 절반 · 전체) 드래그. 카드가 화면에 들어오면 그 핀이 강조 | 한 손으로 지도와 목록을 오간다 |
| A-7 | 결과 화면에서는 헤더의 "무료로 추천받기"를 숨기고 "조건 바꾸기"를 둔다 | — |

### B. 위저드
| # | 과제 | 끝난 상태 |
|---|---|---|
| B-1 | **진행 표시 = 채워지는 영수증**: 상단(모바일은 하단 바)에 작은 영수증이 있고, 단계를 마칠 때마다 한 줄씩 찍힌다(동네 · 목적 · 인원/예산 · 취향) | 진행 막대가 없어지고, "내가 짜고 있는 것"이 항상 보인다 |
| B-2 | 4단계를 "꼭 물을 것"(알뜰/재미 · 이동수단)과 "더 알려 주기"(접힘: 비 · 술 · 야구 · 명물 · 태그)로 나눈다 | 4단계의 첫 화면이 한 뷰포트에 들어온다 |
| B-3 | 선택 카드의 선택 상태를 통일(파란 테두리 + 옅은 파랑 + 체크) | 체크박스 카드와 라디오 카드가 같은 문법 |

## 7. 작업 방법
1. 실행: `apps/api` 에서 `uv run uvicorn app.main:app --port 8000`, `apps/web` 에서 `npm run dev`(포트 3000). 전국 DB 는 `%LOCALAPPDATA%\naegajjanday\`.
2. 고친 뒤: `npm run typecheck` · `npm run lint` · **`npm run verify`**(화면 13개 × 뷰포트 3개, 오류 0 · 사라진 항목 0) · 찍힌 화면을 눈으로. 문구를 일부러 바꿨을 때만 `npm run verify:record`.
3. 기능별 점검 도구(`apps/web/e2e/*-audit.mjs`): 여행 다시 짜기 · 업로드 · 모션 · 밤 코스 · 둘러보기 · 도시 여행 · 대량 검증.
4. 한 과제 = 한 커밋. 토큰을 바꾸면 이 문서의 2절을, 화면 구성을 바꾸면 3절의 캡처를 함께 갱신한다.
