# 34. 앵커 하루 — 대학교 · 축제 (2026-09-23)

창업자 지시 "UNIVERSITY / CAMPUS / FESTIVAL CONTEXT EXPANSION". 대학생 전용 서비스나 새 추천 페이지가 아니다.
기존 **예산 → 목적 → 장소 → 이동 → 영수증**에 **앵커(하루의 중심)**라는 입력 하나를 더한다. 엔진은 그대로다.

## 1. 지금 있는 것 (코드 조사)
- 역 · 장소 주변 코스: `origin` + `origin_label` 로 한 점을 중심으로 하루를 짠다(`_resolve_region` → `nearest_active`).
- 행사도 정류장이 될 수 있다: `events_near` → `event_to_candidate(is_event)` → `CourseStop.event_id`, 화면은 `kind:"event"`.
- 목적 · 템플릿은 데이터(`data/seed/purposes.json`) — 새 목적은 코드 없이 추가된다.
- 없던 것: 대학 데이터(이름에 "대학교"가 든 곳은 전부 "스타벅스 가천대학교점" 같은 가게), 대학 축제 데이터(공식 데이터 없음), 행사의 **시각**(날짜 범위뿐 — 시간 검증 불가).

## 2. 데이터
- **대학**: 공공데이터포털 `전국대학및전문대학정보표준데이터`(표준데이터 15107736, 키 없이 받는 기존 downloader). 1,995행 중 대학 · 전문대학 418곳(대학원 · 사이버 · 방송통신 제외, 같은 학교 두 줄은 하나로). **좌표가 없다** → 우리 장소 DB 의 같은 도로명 · 지번 주소(캠퍼스 안의 가게 · 시설)에서 좌표를 가져온다: 418곳 중 305곳, 그다음 카카오 로컬 검색으로 73곳 → **378곳** (아래 진행 기록). 못 찾은 곳은 넣지 않는다(지어내지 않는다). 카카오 로컬 REST 키가 생기면 나머지를 채울 수 있다.
- 대학은 **장소(Place)** 로 들어간다: 업종 `attraction.campus`(역할 ATTRACTION, 무료, 머무는 시간 45분). 그래서 "캠퍼스 탐방"은 합성 정류장이 아니라 실제 장소 한 곳이고, 저장 · 공유 · 다시 짜기가 그대로 된다.
- **축제 · 행사**: 장소와 분리된 기존 `event` 표에 세 칸을 더한다(마이그레이션 0007) — `anchor_place_id`(어느 대학의 행사인지 = universityId), `start_time` · `end_time`("HH:MM", 시간 검증용), `priority`. 대학 축제는 공식 데이터가 없어 **관리자 화면에서 넣는다**. 캠퍼스 반경 안의 기존 축제(표준데이터 · TourAPI)도 같은 날이면 쓴다.
- 행사 시각이 있으면 그 시간이 곧 영업시간이다(`OpeningPeriod`) → 기존 시간 검증(`is_open` · `slot_window_ok`)이 "축제 시간 때문에 식사 · 이동이 깨지지 않는지"를 본다. 시각을 모르면 지금처럼 날짜만.

## 3. 요청 · 컨텍스트
- `DestinationContext`: `GENERAL_AREA`(지역) · `SPECIFIC_PLACE`(역 · 장소) · `UNIVERSITY` · `FESTIVAL`. enum + 데이터로 움직이는 전략(`app/domain/anchors.py` 의 `plan_for` · `pick_festival` · `campus_first`) 구조 — 나중에 CONCERT · SPORTS · MUSEUM … 을 같은 자리에 붙인다. **이번에는 UNIVERSITY(+그 안의 FESTIVAL)만** 만든다.
- 요청에 `anchor: {kind: "university", id: <장소 public_id>}`. 주면 `origin` = 캠퍼스, `origin_label` = 학교 이름. 응답 echo 에 `anchor: {kind, id, name}` 와 `context`.
- 생활권(반경): 캠퍼스 0~500m · 가까운 동네 500m~1km · 넓게 1~3km. 고정값이 아니라 `data/recommendation/anchor_contexts.json` 의 값 × 이동수단(도보 1 · 대중교통 1.8 · 자동차 2.5). 모자라면 엔진의 기존 반경 확장이 넓힌다.
- 걷는 코스에서 엔진이 중심을 "가장 붐비는 1.5km"로 옮기는 동작(`_settle_on_foot`)은 앵커 코스에서 끈다 — 하루의 중심은 학교다.

## 4. 목적 → 의도 (한 덩어리 "대학 탐방"이 아니다)
대학 컨텍스트에서만 보이는 목적 셋(`anchor_contexts.json` 의 `context_purposes` — 일반 목적 목록에서는 숨는다) + 기존 목적(데이트 · 친구) 재사용:

| 목적 | 의도 | 하루의 틀 | 캠퍼스 정류장 | 반경 비중 |
|---|---|---|---|---|
| 캠퍼스 탐방 `campus` | CAMPUS_WALK · CAMPUS_PHOTO · CAMPUS_LIFE | 캠퍼스 → 식사 → 카페 → (문화 · 놀거리) → (저녁) | 넣는다 | 캠퍼스 ↑ |
| 대학가 맛집 `campus_food` | FOOD | 식사 → 카페 · 디저트 → (식사) | 안 넣는다 | 가까운 동네 ↑ |
| 축제 즐기기 `festival` | FESTIVAL · CAMPUS_LIFE | (캠퍼스) → 식사 → 카페 → **축제** → (뒤풀이 식사) | 선택 | 행사 ↑ |
| 친구 `friends` · 데이트 `date` | FRIENDS · DATE | 기존 템플릿 | 선택(첫 칸) | 가까운 동네 + 경험 |

- 그날 그 학교(또는 캠퍼스 반경)에 행사가 있으면 축제 목적은 그 행사를 CULTURE 칸의 **고정 정류장**으로 쓴다. 없으면 실패하지 않고 캠퍼스 중심 하루로 짜고 `FESTIVAL_NOT_FOUND` 안내("그날 이 학교 행사 정보가 없어 캠퍼스 중심으로 짰어요").
- 다른 목적이어도 그날 행사가 있으면 결과의 "근처 행사"에 뜬다(기존).

## 5. 모자랄 때 (fallback)
대학 데이터 없음 → 검색 결과에 없다(지역 · 역으로 고른다) · 축제 없음 → 캠퍼스 하루 + 안내 · 캠퍼스 주변 장소 부족 → 기존 반경 확장(캠퍼스 → 가까운 동네 → 넓게) · 그래도 부족 → 가장 가까운 활성 지역(`nearest_active`) · 행사 시각 모름 → 날짜만 보고 넣고 시간은 검증하지 않는다(그렇게 적는다).

## 6. 화면
- 위저드 1단계(어디서): "지역 · 역" 옆에 **대학교** 검색(`GET /meta/universities?q=`). 고르면 목적 단계에 대학 목적이 먼저 나온다.
- 결과: 새 페이지 없음. 조건 칩에 🎓 학교 이름, 그날 축제가 코스에 들어가면 🎪 축제. 헤더는 "가천대학교 · 캠퍼스 탐방". 영수증은 그대로(캠퍼스 산책 무료 · 축제 무료/입장료).

## 7. 검증
- 단위: 앵커 해석 · 행사 시각 → 영업시간 · 축제 있는 날/없는 날 · 반경 · 캠퍼스 정류장 포함 여부.
- 통합: 시드에 대학 한 곳 + 그 대학 행사 하나 → `anchor` 로 생성 → 캠퍼스 · 축제 정류장 · echo · 다시 짜기.
- eval: 대학 시나리오(가천대 · 홍익대 · 부산대 … × 목적 셋) — 실패 0, 예산 초과 0.
- 웹: typecheck · lint · verify · qa-pass 에 대학 흐름 한 장면.
