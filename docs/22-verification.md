# 22. 검증 절차 — "오류가 하나도 없어야 내보낸다"

화면을 고쳤으면 아래 네 단계를 **순서대로** 통과해야 끝난 것이다. 앞 단계가 빨리 끝나고 뒤 단계가 비싸다.
HTTP 200 이나 "테스트 통과"만으로는 끝났다고 하지 않는다 — 마지막에는 찍힌 화면을 사람이 직접 본다.

| # | 무엇을 | 명령 (`apps/web` 에서) | 통과 기준 | 걸리는 시간 |
|---|---|---|---|---|
| 1 | 타입 · 린트 | `npm run typecheck` · `npm run lint` | 오류 · 경고 0 | 1분 |
| 2 | **전체 사이클** | `npm run verify` | 문제 0건 | 10분 |
| 3 | 핵심 여정 E2E | `npm run e2e` | 전부 통과 (3개 뷰포트) | 10분 |
| 4 | 눈으로 | `npm run verify -- --shots=폴더` 로 찍힌 전체 화면을 직접 본다 | 어색한 곳이 없다 | — |

API 를 고쳤으면 `apps/api` 에서 `uv run ruff check app tests` · `uv run ruff format --check app tests` · `uv run mypy app` · `uv run pytest -q`, 추천 결과가 달라질 수 있으면 `uv run python -m app.cli eval-courses --scope full --compare full-v5`(docs/18).

## 전체 사이클(`e2e/site-cycle.mjs`)이 하는 일
실제 API 와 전국 DB 를 상대로, 화면 13개 × 뷰포트 3개(데스크톱 1440 · 태블릿 820 · 모바일 Pixel 7)를 돈다.
코스 화면은 실제로 만든 세 가지 코스로 본다: 보통 코스 · 여러 동네 + 비 오는 날 · 1박 2일.
각 화면을 끝까지 스크롤해 늦게 나타나는 구간까지 그리게 하고, 코스 화면에서는 "왜 여기?"와 장소 시트를 실제로 열어 본다.

하나라도 걸리면 종료 코드 1:

| 잡는 것 | 뜻 |
|---|---|
| 페이지 에러 · 콘솔 에러 | 자바스크립트가 터졌다 |
| HTTP 4xx/5xx · 요청 실패 | API · 이미지 · 글꼴 어느 것이든 못 받았다 |
| 에러 화면 | 에러 바운더리나 `INTERNAL_ERROR` 같은 원시 코드가 사용자에게 보였다 |
| 가로 넘침 | 어느 뷰포트에서든 좌우 스크롤이 생겼다 |
| 깨진 이미지 | 받았지만 그려지지 않은 이미지 |
| 이름 없는 버튼/링크 | 스크린리더가 "버튼"이라고만 읽는다 |
| **사라진 것** | 계약서에 있던 제목 · 버튼 · 링크 · 라벨이 화면에서 없어졌다 |

알려진 소음만 예외다(코드 맨 위 `IGNORE_*`): 비로그인 세션 복원의 401, 카카오 SDK 가 타일 없는 거리뷰에 대해 스스로 남기는 로그, 없는 코스를 여는 화면의 의도된 404.
예외를 늘릴 때는 이유를 그 줄에 적는다 — 예외 목록은 "무시해도 되는 것"이 아니라 "왜 무시하는지 설명된 것"만 담는다.

## 화면 계약서 (`e2e/content-contract.json`)
"지금 보이는 것은 디자인을 바꿔도 다 나와야 한다"는 약속을 파일로 만든 것이다.
화면마다 보이는 제목 · 버튼 · 링크 · 라벨의 **뼈대 문구**를 기록한다(가게 이름 · 금액처럼 데이터에 따라 바뀌는 것은 뺀다).

계약서에 **넣지 않는 것**(넣으면 멀쩡한 화면이 실패한다 — 첫 검증에서 27건이 전부 이것이었다):
- 그 동네 · 그 날짜의 데이터: 코스 일정, 지도, 시트, 명소 이름, 공연 · 숙소 · 근처 행사 카드, 예산을 바꿔 본 결과 (`site-cycle.mjs` 의 `DATA`)
- 로딩 중에만 잠깐 보이는 것: `.skeleton-shimmer` 와 `aria-busy` 안의 라벨
- 덜 그려진 화면: 장면마다 "다 그려졌다"는 표식(`ready`)을 기다리고, 스켈레톤이 모두 사라진 뒤에 읽는다

`npm run verify:record` 는 **두 번** 돌고 두 번 다 보인 것만 남긴다(`--intersect`). 한 번만 보인 것은 약속이 아니라 우연이다.

- 문구를 **일부러** 바꾸거나 기능을 더했으면: 바뀐 것이 의도와 같은지 확인한 뒤 `npm run verify:record` 로 다시 기록하고, 계약서의 diff 를 커밋에 함께 넣는다. diff 가 곧 "무엇이 달라졌는지"의 기록이다.
- 계약서를 다시 기록해서 실패를 없애는 것은 검증이 아니다. 사라진 항목이 의도한 것인지 하나씩 읽는다.

## 기능별 점검 도구 (전체 사이클이 보지 않는 흐름)
전체 사이클은 "화면을 열었을 때"를 본다. 버튼을 눌러야 드러나는 흐름은 작은 점검 도구가 따로 본다. 모두 실제 API 상대, 실패하면 종료 코드 1.

| 도구 (`apps/web/e2e/`) | 보는 것 |
|---|---|
| `trip-reroll-audit.mjs` | 1박 2일의 1일차를 "다시 짜기" 해도 일차 · 탭 · 여행 전체 예산이 그대로인지, 가족 + 술 한잔이면 결과 화면이 그 사실을 말하는지, 자료 없는 평점 막대를 그리지 않는지 |
| `upload-audit.mjs <토큰 파일>` | 관리자 › 장소 › 사진 탭: 미리보기, 사진 아닌 파일 거절, multipart 모양(`file` + `make_cover`). 실제 가게에 시험 사진이 남지 않게 업로드 요청은 가로채서 내용만 확인한다 |
| `night-audit.mjs` | 새벽 2시(도보) · 밤 11시(차) 출발로 실제 코스를 만들어: 두 곳 이상 들르는지, 결과 화면이 "영업시간을 추정했다"고 말하는지, 멀리 있는 전망대까지 **모든 핀이 지도 안에** 있는지 |
| `motion-audit.mjs` | 영수증 "출력" 애니메이션이 끝난 뒤 모든 줄이 온전히 보이는지, 모션을 줄인 환경(`prefers-reduced-motion`)에서는 처음부터 다 보이는지 |
| `map-audit` · `local-audit` · `trip-audit` · `roadview-audit` · `place-audit` | 지도 경로 · 동네 특색 · 여행 일정 · 거리뷰 · 장소 시트 |

## 검증기가 실제로 잡은 것 (기록)
- 코스의 가게마다 거리뷰를 잇달아 열면 페이지 전체가 에러 화면이 되던 문제(카카오 SDK 컨테이너 안의 React 자식).
- 위저드의 동네 추가 버튼 문구에 "다음"이 들어가 "다음" 버튼과 구분되지 않던 문제.
- 공연 카드가 말없이 안 뜨던 문제(API 가 20초 걸리는데 웹은 15초에 포기).
- 검증기 자신의 오탐: 카카오 지도의 확대 · 축소 버튼은 `title` 로 이름이 있다 → 이름 판정에 `title` 을 넣었다.
- 업로드 점검이 잡은 것: 파일 입력과 제출 버튼의 이름이 둘 다 "사진 올리기"였다(스크린리더에서 구분 불가) → 입력 라벨을 "올릴 사진"으로.
- 설계 점검(코드 읽기)이 잡은 것: 여행의 하루를 다시 짜면 그 날이 여행에서 떨어져 나가고, 하루만 저장하면 나머지 날이 보존 기한에 지워지던 문제 → `replaces` · 여행 통째 저장.
- 밤 코스 점검이 잡은 것: 차로 25분 떨어진 전망대가 코스에 들어가자 지도가 핀이 하나도 없는 중간 지점을 확대해 보여 줬다(확대 제한이 "동네 하나"를 가정) → 확대 제한은 길이 돌아간 만큼에만 걸고, 모든 핀은 언제나 화면 안에.
