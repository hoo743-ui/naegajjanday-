# 56. CI — 무엇이 돌고, 어떻게 읽고, 로컬에서 어떻게 똑같이 돌리나

> 2026-09-26. 그전까지는 main 에 푸시할 때마다 CI / API · CI / Web · Security 가 전부 빨간색이었고 아무도 몰랐다.
> 원인: (1) pytest 잡이 운영과 다른 PostGIS+Redis 설정에 `RATE_LIMIT_ENABLED=false` 를 환경변수로 흘려 레이트리밋
> 테스트가 깨졌다, (2) e2e 잡이 목(MSW)으로 돌도록 되어 있었지만 e2e 는 실제 API 를 전제로 쓰였다,
> (3) Docker 이미지에 베이스 이미지의 npm · pip(와 그 의존성)이 남아 Trivy 가 HIGH 로 잡았다.

## 1. 무엇이 도나

| 워크플로 | 언제 | 잡 | 막는 것 |
|---|---|---|---|
| **CI / API** (`ci-api.yml`) | `apps/api/**` 가 바뀐 푸시·PR | `ruff + mypy` — ruff check · `ruff format --check` · mypy | 문법·형식·타입 |
| | | `pytest (sqlite, like production)` — 운영(Render)과 같은 **SQLite** + Python 3.13. 먼저 Render 의 시작 경로(`db init` → `seed-config` → `ingest --provider file --all`)를 새 파일에 돌려 본 뒤 전체 테스트(700+) | 엔진·API 회귀, 새 DB 에서 서버가 못 뜨는 것 |
| | | `docker build (no push)` | Dockerfile 이 깨지는 것 |
| **CI / Web** (`ci-web.yml`) | `apps/web/**` **또는 `apps/api/**`** 가 바뀐 푸시·PR | `lint + typecheck + build` | 린트 · 타입 · `next build` |
| | | `e2e (real API on seed SQLite) + phone screenshots` — 실제 API 를 시드 SQLite 로 띄우고, 웹을 standalone 으로 빌드해 `e2e/journey.spec.ts` 를 휴대폰(Pixel 7) · 데스크톱에서 돌린 뒤 390px 화면 사진을 찍는다 | 웹↔API 계약 불일치, 핵심 여정(홈 → 위저드 → 코스 → 결과), 콘솔 에러, 가로 넘침 |
| **Security** (`security.yml`) | 모든 푸시·PR + 매주 월요일 | CodeQL(python · js/ts) · gitleaks · (PR) dependency review · **Trivy** 이미지 스캔(api · web) | 알려진 취약점(고칠 수 있는 HIGH/CRITICAL), 비밀값 커밋 |

e2e 에 대해:
- 목(MSW)이 아니라 **실제 API** 다. 목은 실제 응답과 어긋나도 통과하기 때문이다(목↔실API 계약 불일치를 잡는 것이 e2e 의 첫 목적).
- DB 는 `apps/api/data/seed` (지역 8곳 · 가짜 장소 120곳). 전국 DB 에 기대는 두 검사 — 경기도·수원시 지역 나무, "재미 우선"에 공원 대신 놀거리 — 는 시드 DB 에서 스스로 건너뛴다(`hasNationwideData`). 전국 DB 로 로컬에서 돌리면 전부 돈다.
- 레이트리밋은 끈다(여정 하나가 익명 코스를 10개 넘게 만든다). 외부 길찾기(OSRM)도 끈다 → 걷는 구간은 엔진 추정치.
- 브라우저는 러너에 깔린 Google Chrome 을 쓴다(내려받지 않는다). 목표 15분 이내.

Trivy 에 대해:
- **운영은 이 이미지를 쓰지 않는다.** API 는 Render 가 소스에서 빌드하고(`render.yaml`, 네이티브 Python), 웹은 Vercel 이 Next.js 로 빌드한다. 이미지는 AWS/compose 경로용이다. 그래도 게이트는 끄지 않는다 — 그 경로로 옮기는 날 이미 깨끗해야 한다.
- 예외는 루트 `.trivyignore` 에만, 한 줄마다 이유와 만료일을 붙인다. 뭉뚱그린 예외는 금지.

## 2. 결과 읽는 법

- 저장소 › **Actions** › 커밋을 누르면 세 워크플로가 보인다. 빨간 잡 › 빨간 단계를 펼친다(로그는 로그인해야 보인다).
- 로그인 없이 상태만: `curl https://api.github.com/repos/hoo743-ui/naegajjanday-/actions/runs?per_page=5`, 그다음
  `/actions/runs/{id}/jobs` (시간당 60회 제한).
- **휴대폰 화면 사진**: e2e 잡의 실행 요약 맨 아래 **Artifacts › `mobile-screens`** (30일 보관).
  `01-home` · `02-wizard-where` · `03-course-result` — 각각 첫 화면(`.png`)과 페이지 전체(`-full.png`).
  페이지 전체 사진에서 하단 고정 바가 중간에 찍히는 것은 캡처 방식 때문이고 결함이 아니다.
- e2e 가 실패하면 **`playwright-report`** 아티팩트(리포트 + 실패 스크린샷 + trace)와, 잡 로그의 "Server logs" 단계(api.log · web.log 끝부분)를 본다.
  trace 는 `npx playwright show-trace <trace.zip>` 로 연다.
- API 커버리지: pytest 잡 요약의 "API coverage: N%" 와 `api-coverage` 아티팩트.
- Trivy 결과 전체(SARIF): Security 탭 › Code scanning (저장소 관리자만).

## 3. 로컬에서 똑같이

API (apps/api):
```bash
uv sync
uv run ruff check . && uv run ruff format --check . && uv run mypy app
uv run pytest -q          # 환경변수 없이. conftest 가 임시 SQLite 를 시드로 채운다
```
`RATE_LIMIT_ENABLED` 같은 값을 셸에 export 해 둔 채 돌리면 테스트가 깨질 수 있다 — CI 가 그렇게 깨졌었다.

Web (apps/web):
```bash
npm ci && npm run lint && npm run typecheck
```
`next build` 는 OneDrive 폴더 안에서 돌리지 않는다(.next 가 깨진다) → `apps/web` 을 %TEMP% 에 복사해서 빌드한다.

e2e (CI 와 같은 구성, 포트는 CI 기준):
```bash
# 1) API — 시드 SQLite
cd apps/api
export DATABASE_URL=sqlite+aiosqlite:///./e2e.db RATE_LIMIT_ENABLED=false OSRM_FOOT_URL=
uv run python -m app.cli db init && uv run python -m app.cli seed-config && uv run python -m app.cli ingest --provider file --all
uv run uvicorn app.main:app --port 8000 &
# 2) 웹 — standalone (OneDrive 밖의 복사본에서)
NEXT_PUBLIC_API_URL=http://localhost:8000/v1 npm run build
cp -r .next/static .next/standalone/.next/static && cp -r public .next/standalone/public
PORT=3000 node .next/standalone/server.js &
# 3) 여정 + 사진 (사진은 e2e-screens/)
npx playwright test --project=mobile --project=desktop
npx playwright test --project=screens
```
전국 DB 를 상대로 돌리려면 1) 대신 평소 API 를 띄우면 된다. 다른 포트는 `E2E_BASE_URL` · `E2E_API_URL` (웹 포트를 바꾸면 API 의 `CORS_ORIGINS` 도).

Trivy (도커 없이도 된다): `trivy image python:3.13-slim`, `trivy fs apps/web/package-lock.json` 처럼 베이스 이미지와 lockfile 을 따로 본다.
